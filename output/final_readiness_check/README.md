# 마지막 자료 수신 및 분석 준비 점검 — 2026-09-29

이 문서는 수정 전 점검 기록이다. 후속 수정과 최신 검증은 [실행 준비 검증](../workflow_readiness_validation/README.md)을 따른다. 원본 연도 불일치는 여전히 미해결이다.

## 판정: 최종 보고서 실행 준비 미완료

### 수신 자료

사용자가 2026년 Day 6로 지정한 JSON을 `data/intake_pending_year_confirmation/`에 원형 보관했다. JSON 내부에는 2025-09-29, 제80차 총회, A/80/PV.15가 명시되어 있다. 기존 2025년 Day 6 TXT와 제목·날짜·출처 URL도 일치한다. 2026년 입력으로 등록하지 않았으며 연도 확인을 요청했다. 수신 정보는 `received_source.json` 참조.

### 실행 점검

- `python -m unga_analysis analyze`로 무료 준비 점검 실행. `--execute`를 실행하지 않았다.
- 1,888개 연설, 49,912개 문단. 2026년은 171개 연설, Day 1–5만 반영되어 있다.
- 의존성 설치 및 API 키 존재 확인. 이번 점검에서 API 접속이나 유료 추론은 수행하지 않았다.
- `ready_for_execution=false`. `ready_after_final_day=true`는 현재 preflight 코드가 의존성·키 관련 problems가 없는지만 확인해 산출하는 값이다. 구독 작업량·보고서 내용 요건까지 충족했다는 의미가 아니다.
- unittest discovery의 72개 테스트 모두 통과(24.336초). 전체 테스트 실행 중 `openai.OpenAI`를 예외 발생 mock으로 대체해 실제 클라이언트 생성을 차단했다. 기존 테스트의 가짜 provider/client만 사용했다.
- 합성 입력의 검토→분류→집계→Word/PDF 연결은 확인되었다. 실제 코퍼스 전체의 구독 처리량과 실질적인 보고서 품질을 검증한 것은 아니다.

### 남아 있는 실행·보고서 결함

1. 전체 텍스트를 두 번 검토하므로 검토 요청만 4,370개다. 직전 실제 코퍼스의 오프라인 재현에서 세 번 모두 미응답 요청 5개 생성 후 중단했다. 이번 점검에서도 관련 코드와 설정에 변경은 없다.
2. 단계별 요청 사전 생성과 분류 묶음 처리가 아직 없다. 검토 범위를 줄이는 경우 미검토를 No로 바꾸지 않도록 분모·검토 범위 정의도 함께 조정해야 한다.
3. 보고서의 각 섹션은 최대 2문단×90단어다. Themes의 주제 4–6개별 발견·국가 차이·인용을 담기에는 부족하다.
4. 직접 PDF 생성은 섹션별 한 페이지 고정이며 글자 축소 후에도 넘치면 실패한다. Word는 5–6페이지로 넘칠 수 있으나 유연한 지면 설계는 아니다. 내부 근거 키도 본문에 노출된다.

이번 요청에서는 파일 보관과 준비 상태 검증을 수행했다. 분석 방식·프로토콜·실행 코드의 변경, 실제 분석, 커밋·푸시는 수행하지 않았다. 올바른 2026년 Day 6 수신만으로 위 실행·보고서 결함이 해결되지는 않는다.

기존 data 파일, speeches.jsonl, source_manifest.jsonl의 전후 비교는 `protected_integrity.json`에 기록한다. 신규 대기 원본과 보관 설명서는 기존 DB 변경과 구분한다.

# 분석 실행 준비 수정·검증 — 2026-09-29

## 판정

실행 코드와 보고서 생성 경로의 수정 및 오프라인 검증을 완료했다. 실제 2026년 Day 6가 내부 연도·회기 검사를 통과하고 기존 준비 절차로 반영되면, 같은 Codex 구독 세션이 요청을 검토하고 재개하여 Word/PDF와 근거 파일까지 생성하는 경로다. 사용자가 요청 JSON을 수동 작성할 필요는 없다.

현재 `ready_for_execution=false`인 이유는 **2026년 Day 6 미확보**다. 최근 첨부 파일은 내부 날짜가 2025-09-29, 회기가 UNGA80이므로 2026년으로 등록하지 않았다. 원본은 연도 확인 대기 폴더에 보관했다. 실제 구독 한도·모델 가용성·새 파일의 전처리 결과까지 미리 보장하는 것은 아니다. 검증 중 실제 분석이나 유료 API 호출은 없었다.

## 변경 사항

| 문제 | 수정 |
|---|---|
| 미응답 몇 건에서 요청 생성 중단 | 현재 단계의 독립 요청을 모두 생성하고 pending_requests.json으로 전달. 후속 단계는 선행 답변 검증 후 생성 |
| 전체 코퍼스 2회 검토 | 후보 연설은 전체 문맥 1회, 음성 표본은 연도×지역×출처별 2편씩 2회, 다른 선택 연설의 10%도 2회. 표본에서 Yes/Uncertain 발견 시 해당 집단으로 확대 |
| 미검토 국가와 분모 문제 | 미검토는 Pending/NA. 연도·지역별 비율은 확보 자료 대비 확인된 AI 언급의 최소 비율. 모집단 비율로 해석하지 않음. 주제별 0은 여전히 전체 연설 AI 검토와 해당 코드 No 확인이 필요 |
| 문단마다 taxonomy 반복 | 최대 8문단·28,000문자 단위로 공통 정의를 한 번 전송. 예시는 분류용 정의에서 제외. 두 판정의 불일치는 Uncertain 유지 |
| 보고서 내용·고정 페이지 | Themes 최대 6문단, Role of UN 최대 4문단. 섹션이 페이지를 넘어 이어지는 4–6페이지 구성. 본문 10.5pt 유지. 넘치면 근거를 보존하는 편집 요청 |
| 내부 인용 키 노출 | 번호·국가/연도로 표시하고 Report_Sources.md 및 JSON 근거표에 원문·위치·통계 연결. 본문 인용문도 인용한 원문과 대조 |
| 잘못된 연도 자료 수신 | 날짜·회기·영어·Day 6 검사 후 수신. JSON 전처리에서도 파일명/내부 날짜 충돌 차단 |
| Word 그림 잘림 | 인라인 그림 문단에 자동 줄 높이 적용. 실제 Microsoft Word 변환과 페이지 이미지 확인 |
| 열린 Office 문서의 임시 파일 | ~$ 소유자 파일을 참고자료·실행 식별 해시에서 제외 |
| Windows의 일시적인 출력 파일 잠금 | 기존 결과를 삭제하지 않고 원자적 교체를 제한된 횟수로 재시도 |

국가 단위 주제의 No를 제대로 판단하기 위해 후보 문단만 따로 읽는 대신 **후보가 나온 연설 전체**를 읽는다. 검토 범위 축소로 인한 탐지 누락·연도별 선택 편향은 보고서 방법·한계에 명시한다. 세 번째 조정 판정은 도입하지 않았다.

## 실제 코퍼스에서 측정한 작업량

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 최초 검토 대상 연설 | 1,888편 | 541편: 후보 437 + 음성 표본 104 |
| 최초 검토 요청 | 4,370개 | 768개 |
| 검토 입력 문자: 본문·지시·schema | 63,493,527 | 11,711,464 |
| 후보 666문단 기준 분류 요청 추정 | 1,332개 | 242개 |

실제 코퍼스를 읽되 임시 작업 공간에서 요청만 생성하여 **768개가 첫 호출에 모두 생성됨**을 확인했다(약 2.7초). 검토 입력량은 약 82% 감소했다. 답변 토큰은 별도이며 음성 표본에서 누락이 발견되면 추가 검토한다. 분류량은 실제 AI 판정과 taxonomy 길이에 따라 달라진다. 임베딩 비용은 기존 설정의 후보 기반 추정 약 $0.05, 직접 API 누적 상한 $1이다. 구독 사용량과 완료 시간을 보장하는 수치는 아니다.

## 검증 근거

- 전체 unittest discovery: **90개 통과**, 실제 OpenAI 클라이언트 생성은 mock으로 차단. 자세한 결과: `tests.log`.
- 새 방식의 요청 생성 → 가짜 구독 응답 → 탐색 → 묶음 분류 → 집계 → Word/PDF 연결 검증.
- 원문 인용, 불일치, 미검토 Pending, 최소 확인 비율, 표본 확대, 요청 전체 생성, 묶음 ID·인용 오류, 잘못된 연도, 보고서 축약 요청, Office 임시 파일·잠금 회귀 검증.
- 긴 합성 보고서를 실제 Microsoft Word에서 변환하고 4페이지·차트 표시·섹션 이어짐을 확인. 별도 밀도 시험에서는 5–6페이지도 허용되는지 검증. `layout/checks.json`과 `layout/SYNTHETIC_FINAL_LAYOUT.docx`, `.pdf` 참조. 이 문서는 **합성 배치 검증용이며 실제 국가 분석 결과가 아니다.**
- 기존 보호 대상 2,009개 파일의 SHA256 변경 0. `data/`, 정규화 DB, source manifest를 다시 생성하지 않았다. 이전 턴에서 저장한 확인 대기 원본은 활성 분석 입력 밖에 있다.
- `speeches.jsonl` 전후 SHA256: `e78fc96b4666cdd5125d640ec814a736301f530d89bba91491695734f60c2eb0`.
- 유료 API 호출 0. 실측·해시·준비 상태: `validation.json`.

Word 자동화는 제한된 실행 환경에서 시간 초과할 수 있다. 이 경우 독립 PDF/DOCX를 보존하고 Codex가 일반 사용자 환경에서 같은 로컬 변환 스크립트로 최종 확인한다. 이번 실제 Word 검증도 이 경로로 완료했다.

원격 푸시는 수행하지 않았다. 실행 안내는 `docs/ANALYSIS_WORKFLOW.md`, 방법 변경은 `ANALYSIS_PROTOCOL.md`에 반영했다.
